# Public Repository Readiness

## What Can Be Public

- Source code in this repository.
- Small fixture files under `tests/fixtures/`.
- Derived static outputs generated by GitHub Actions: `rss.xml`, `feeds/changes.xml`, and `static/*.json`.
- Official source URLs and deterministic hashes.

## What Must Not Be Committed

- `.env` files, API keys, tokens, webhook URLs, private Slack/email credentials, or personal access tokens.
- Runtime crawler storage under `storage/`.
- Generated static output under `public/`.
- Downloaded official CSV/PDF/XLSX payloads in repository history.
- Machine-specific absolute paths, hostnames, or local trust settings.

## GitHub Pages Setup

1. Push the repository to GitHub.
2. In repository settings, enable Pages with source `GitHub Actions`.
3. Optionally set repository variable `CHITAN_WATCH_SITE_URL` to the final public base URL, for example `https://example.com/chitan-watch`.
4. Run the `Publish static Chitan Watch feed` workflow manually once.
5. Subscribe RSS readers or Slack RSS app to `<site-url>/rss.xml`.

## No-Secret Policy

The workflow requires no custom secret. It uses only GitHub-provided Pages permissions:

- `contents: read`
- `pages: write`
- `id-token: write`

The crawler state is cached by GitHub Actions so the next scheduled run can compare against the previous run. This cache may contain copies of public official artifacts; it must not contain credentials.

## Slack RSS

After Pages is live, Slack can subscribe with:

```text
/feed subscribe https://<your-pages-url>/rss.xml
```

If a custom domain is used, set `CHITAN_WATCH_SITE_URL` so RSS item links point to the public site.
